# BUG-009: Celah Keamanan Auto-Link Akun WhatsApp (Unregistered Sender)

## Deskripsi Masalah (Why)
Ditemukan celah keamanan (security vulnerability) serius pada *WhatsApp Bridge* dan *ChatOrchestratorService* di Backend. Bot merespons pesan dari **nomor WhatsApp yang tidak terdaftar** dengan cara yang tidak aman.

Alih-alih menolak dan meminta pengguna mendaftar, logika `findUser()` memiliki blok "fallback" yang secara otomatis mengaitkan (auto-link) nomor tidak dikenal tersebut (LID-nya) ke pengguna pertama (`User::first()`) di dalam database. Akibatnya, orang asing bisa mengakses dan memanipulasi data keuangan pengguna lain melalui WhatsApp.

## Akar Masalah (Root Cause)
Pada `app/Services/Chat/ChatOrchestratorService.php`, terdapat logika *fallback* untuk skenario pengembang tunggal (solo dev) yang tidak dihilangkan untuk environment produksi:

**Kode Sebelum (Berbahaya ❌):**
```php
        // The identifier might be a LID that we haven't seen before
        // For solo dev / small scale: auto-link to the first verified user
        if ($dto->replyJid && str_contains($dto->replyJid, '@lid')) {
            // Find users who have a verified phone number
            $user = User::whereHas('phoneVerifications', function ($q) {
                $q->whereNotNull('verified_at');
            })->first();

            // Fallback: just get the first user (solo dev scenario)
            if (!$user) {
                $user = User::first(); // Bencana keamanan terjadi di sini!
            }

            if ($user) {
                $user->update(['wa_lid' => $identifier]);
                Log::info('Auto-linked LID to user', ['user_id' => $user->id, 'lid' => $identifier]);
                return $user;
            }
        }
```

## Solusi (How to Solve)
Langkah perbaikannya adalah dengan **menghapus fallback** tersebut dan memberlakukan aturan validasi yang sangat ketat:
1. Pengecekan nomor HP (`phone_number`) wajib menyertakan validasi bahwa nomor tersebut **telah diverifikasi** di database (punya `verified_at`).
2. Pengecekan LID (`wa_lid`) hanya diperbolehkan jika LID tersebut sudah pernah tertaut pada pengguna yang valid sebelumnya.
3. Nomor yang tidak dikenal sepenuhnya **ditolak (REJECTED)** dan fungsi akan mengembalikan `null`. Bot otomatis membalas dengan perintah untuk melakukan registrasi.

**Kode Sesudah (Aman ✅):**
```php
    private function findUser(IncomingMessageDTO $dto): ?User
    {
        $identifier = $dto->phoneNumber;

        // 1. Try direct phone number match — must be a registered AND verified user
        $user = User::where('phone_number', $identifier)
            ->whereHas('phoneVerifications', function ($q) {
                $q->whereNotNull('verified_at');
            })
            ->first();

        if ($user) {
            // Auto-link LID on first contact so future messages via LID still work
            if ($dto->replyJid && str_contains($dto->replyJid, '@lid') && !$user->wa_lid) {
                $lid = str_replace('@lid', '', $dto->replyJid);
                $user->update(['wa_lid' => $lid]);
                Log::info('Linked WA LID to verified user', ['user_id' => $user->id, 'lid' => $lid]);
            }
            return $user;
        }

        // 2. Try LID match — only if this LID is already tied to a known user
        if (!empty($identifier)) {
            $user = User::where('wa_lid', $identifier)->first();
            if ($user) {
                return $user;
            }
        }

        // 3. No match — reject the sender entirely.
        Log::warning('WA message from unrecognized / unverified sender', [
            'identifier' => $identifier,
            'reply_jid'  => $dto->replyJid,
        ]);

        return null;
    }
```
