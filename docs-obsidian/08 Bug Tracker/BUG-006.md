# BUG-006: Profile Information Not Displayed on settings page/sidebar after login/register

## Deskripsi
Ketika pengguna masuk (*login*) atau melakukan registrasi baru, mereka dapat diarahkan ke halaman dasbor. Namun, informasi profil seperti nama, email, dan nomor WhatsApp pada halaman Pengaturan (Settings) dan nama pengguna di pojok kiri bawah *sidebar* tidak muncul (hanya menampilkan data kosong atau teks bawaan `"User"`). Masalah ini hanya teratasi sementara jika pengguna melakukan *force reload* (*refresh* halaman secara manual).

## Alasan / Root Cause
Penyebab utamanya adalah halaman login (`app/login/page.js`) dan halaman registrasi (`app/register/page.js`) memanggil kelas koneksi HTTP `api.login()` dan `api.register()` secara langsung di bawah kap. 
Mereka tidak menggunakan fungsi `login` dan `register` yang disediakan oleh `AuthContext`. Akibatnya:
1. Kunci token baru berhasil disimpan ke dalam `localStorage` dan `cookies`.
2. Namun, *state* internal React untuk data pengguna (`user`) yang berada di dalam `AuthContext` **tidak pernah terupdate** dan tetap bernilai `null`.
3. Karena Next.js melakukan perpindahan rute secara *client-side* (`router.push('/dashboard')`), objek provider `AuthProvider` tidak dilepas (*unmounted*), sehingga `fetchUser()` tidak terpicu ulang pada saat navigasi. Profil pengguna tetap kosong hingga halaman di-refresh secara penuh.

## To-Do
- Mengubah proses pengiriman form di `LoginPage` agar memanggil fungsi `login` dari hook `useAuth()`.
- Mengubah proses pengiriman form di `RegisterPage` agar memanggil fungsi `register` dari hook `useAuth()`.
- Memastikan token disimpan dan `fetchUser` dipanggil secara otomatis oleh context sesaat setelah otentikasi berhasil sebelum dialihkan ke dasbor.

## How to Solved
1. Memperbarui `finance-app-web/app/login/page.js` untuk mengimpor `useAuth` dari context dan mendestruktur fungsi `login`. Mengganti pemanggilan `api.login(...)` menjadi `login(...)`.
2. Memperbarui `finance-app-web/app/register/page.js` untuk mengimpor `useAuth` dan menggunakan fungsi `register(...)`.
3. Dengan perubahan ini, sesaat setelah API mengembalikan respons sukses, `AuthContext` langsung menjalankan `fetchUser()`, memperbarui data profil pengguna di tingkat global, dan barulah dialihkan ke `/dashboard`. Semua komponen (termasuk *sidebar* dan halaman *settings*) langsung ter-render dengan nama asli pengguna (misal: "QA Tester").
