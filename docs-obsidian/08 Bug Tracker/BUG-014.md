# BUG-014: Rate Limiter Nomor Tidak Dikenal Gagal (Spam Balasan)

## Deskripsi Masalah (Why)
Pengguna yang tidak terdaftar mengirim pesan ke bot dan mendapatkan pesan balasan (greeting) berkali-kali jika mereka terus mengirim pesan. Seharusnya (berdasarkan BUG-010), bot hanya membalas sekali per 24 jam. Namun kenyataannya, setiap pesan masuk selalu memicu balasan.

## Akar Masalah (Root Cause)
1. Kolom `user_id` di tabel `chat_messages` bersifat **NOT NULL**.
2. Saat `UnregisteredUserService` mencoba merekam bahwa pesan sapaan telah dikirim (`recordGreetingSent`), operasi `INSERT` ke database gagal dengan error: `General error: 1364 Field 'user_id' doesn't have a default value`.
3. Karena penyimpanan riwayat selalu gagal, saat pesan berikutnya masuk, bot menganggap belum pernah ada sapaan (record tidak ditemukan), sehingga bot membalas lagi, gagal menyimpan lagi, dan seterusnya (infinite loop spam).
4. Ada kondisi *race condition* kecil dimana kode lama mengirimkan pesan WA terlebih dahulu (`sendMessage()`) sebelum merekamnya di database (`recordGreetingSent()`). Ini menyebabkan pesan tetap terkirim walaupun operasi database error.

## Solusi (How to Solve)
1. **Migration (Database)**: Membuat file migration baru (`2026_08_26_055844_make_user_id_nullable_in_chat_messages.php`) untuk mengubah tipe kolom `user_id` pada `chat_messages` menjadi `nullable()`. Hal ini memungkinkan rekaman histori pesan dari nomor tidak dikenal tanpa memiliki `user_id` yang valid.
2. **Reorder Logic**: Mengubah urutan operasi pada `ChatOrchestratorService::handleUnregisteredUser()`. Metode sekarang merekam ke dalam database *terlebih dahulu* (`recordGreetingSent`), dan *baru kemudian* mengirimkan pesan via WhatsApp (`sendMessage`). Hal ini memastikan bahwa jika ada masalah di database, pesan tidak akan dikirim.

## Status
✅ Terselesaikan dan sudah di-*deploy*. Spam sudah hilang dan record histori nomor yang tidak terdaftar sudah berhasil disimpan.
