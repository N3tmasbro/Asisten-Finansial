# BUG-005: Infinite Redirect Loop on Stale Token (Frontend)

## Deskripsi
Halaman frontend (*browser*) pengguna secara non-stop memuat ulang (*refresh*) tiada henti ketika mengakses halaman seperti `/dashboard`. Halaman berkedip sangat cepat memuat logo kemudian me-refresh terus-menerus dan halaman hanya berhenti jika diintervensi manual dengan menghapus data/cookie lokal (`Ctrl+Shift+Del`).

## Alasan / Root Cause
Kejadian ini disebabkan oleh "Perang Redirect" (Race Condition) antara server-side dan client-side saat menangani *Auth Token* kedaluwarsa atau tidak valid (HTTP 401 Unauthorized):
1. **Server (`proxy.js`)**: Memeriksa *apakah cookie ada?* Karena cookie `auth_token` usang masih ada, server meneruskan (mengizinkan) permintaan halaman ke `/dashboard`.
2. **Client (`AuthContext`)**: Saat halaman dimuat, client mengambil profil dari backend. API melempar *HTTP 401* (token sudah tidak valid di database).
3. **Client (`api.js`)**: Menangkap *error 401*, menghapus cookie, kemudian *memaksa memuat ulang seluruh halaman* dengan `window.location.replace('/login')`.
4. **Masalah Kronis (Timing Issue)**: Tindakan pemuatan ulang seluruh halaman ini mereset memori eksekusi `api.js`. Akibatnya, `api.js` belum menyadari bahwa ia telah membuang tokennya, dan kadang-kadang sinkronisasi lokal kembali gagal/diinterupsi ulang (terlebih ada dualisme fungsi penghapusan token). Begitu halaman di-refresh, siklus berulang, yang menyedot koneksi tiada akhir.

## To-Do
- Menghapus logika redirect brutal menggunakan `window.location.replace()` dari kelas kelas utilitas koneksi `api.js`. 
- Menjadikan `AuthContext.js` sebagai pusat komando sirkulasi navigasi halaman otentikasi tunggal (Single Source of Truth).
- Memanfaatkan Client Router Next.js (`useRouter()`) ketimbang re-render memori lokal, agar *state* halaman tetap stabil dan mulus.

## How to Solved
1. Memodifikasi `finance-app-web/lib/api.js`. Pada bagian *handler* respons status `401`, fungsi `window.location.replace('/login')` **dihapus**. `api.js` kini hanya membuang (membersihkan) token lalu melempar *exception error* agar level komponen React yang mengurus navigasinya.
2. Memodifikasi `finance-app-web/contexts/AuthContext.js`.
3. Menambahkan *hook* Next.js `useRouter` dan `usePathname`. Jika status *loading* otentikasi selesai (`!isLoading`) namun pengguna (`user`) tidak ada dan dia berada di rute terlindungi (*Protected Route*), barulah aplikasi menggunakan `router.replace('/login')` satu kali saja secara aman (client-side routing, tanpa *full-page reload*).
4. Bug teratasi. Saat cookie tidak valid, pengguna akan dilempar ke `/login` sekali dengan mulus tanpa loop layar.
