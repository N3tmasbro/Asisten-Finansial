# BUG-015: Chatbot Mengirim `{}` ke WhatsApp saat Gemini Rate Limit Habis

## Deskripsi Masalah (Why)
Saat API Gemini terkena *rate limit* (HTTP 429) dan semua model *fallback* juga habis kuotanya, bot WhatsApp mengirimkan pesan teks literal **`{}`** kepada pengguna alih-alih pesan error yang ramah. Hal ini teridentifikasi saat *stress test* 100 transaksi yang memicu ~200 API calls dalam waktu singkat.

Screenshot: Terlihat di chat WhatsApp pengguna ada 2 pesan `{}` berturut-turut di antara pesan balasan yang normal.

## Akar Masalah (Root Cause)
Di dalam `GeminiProvider.php`, fungsi `executeGeminiRequest()` me-return string literal `'{}'` sebagai *last-resort fallback*:

```php
// Baris 558: Ketika error non-429/404
return '{}';

// Baris 571: Ketika SEMUA fallback model habis/rate-limited
return '{}';

// Baris 529: Default jika response candidates kosong
$text = $candidates[0]['content']['parts'][0]['text'] ?? '{}';
```

String `'{}'` ini kemudian diteruskan langsung oleh `formatResponse()` → `logAndSend()` → `sendMessage()` → **dikirim ke WhatsApp sebagai pesan teks biasa**.

## File yang Terdampak
- `app/Services/AI/Providers/GeminiProvider.php` — baris 529, 558, 571
- `app/Services/Chat/ChatOrchestratorService.php` — fungsi `logAndSend()`, tidak memvalidasi apakah `$responseText` berupa `'{}'`

## Solusi yang Direkomendasikan (Belum Diimplementasikan)
1. **Di `GeminiProvider.php`**: Ubah return value fallback dari `'{}'` menjadi `null` atau throw sebuah custom Exception (misal: `GeminiRateLimitException`).
2. **Di `callGemini()` (untuk free-text)**: Tambahkan validasi setelah pemanggilan — jika `executeGeminiRequest()` mengembalikan `'{}'` atau string kosong, kembalikan string error yang ramah pengguna:
   ```php
   $result = $this->executeGeminiRequest($payload);
   if (empty($result) || $result === '{}') {
       return "Maaf, asisten sedang sibuk 😅 Coba lagi sebentar ya!";
   }
   return $result;
   ```
3. **Di `ChatOrchestratorService::logAndSend()`**: Tambahkan guard sebelum `sendMessage()` — jika `$responseText` adalah `'{}'` atau kosong, ganti dengan pesan error default.
