# BUG-011: Status Bad MAC Latching pada WhatsApp Bridge (False Offline)

## Deskripsi Masalah (Why)
Di halaman Pengaturan web, indikator koneksi WhatsApp terus-menerus menampilkan status **"Tidak Terhubung"** dengan pesan error *"Terdeteksi Bad MAC (Sesi enkripsi WhatsApp rusak). Silakan hubungkan ulang."* padahal bot WhatsApp di backend sebenarnya masih dapat berkirim dan menerima pesan secara normal.

## Akar Masalah (Root Cause)
Di file `whatsapp-bridge/src/index.js`, terdapat logika override `console.error` yang menangkap kata *"Bad MAC"* atau *"Failed to decrypt message"* (yang merupakan error dekripsi pesan transient/sesaat di Baileys WhatsApp) dan mengubah variabel `hasBadMacError = true`.

Variabel `hasBadMacError` ini bersifat permanen (latching) di dalam memori Node.js bridge. Akibatnya, API `/status` pada bridge akan selamanya mengembalikan status `disconnected` hingga proses Node.js di-restart manual, meskipun koneksi WhatsApp utama (`sock.user`) masih terhubung dan sehat.

## Solusi (How to Solve)
1. Menghapus variabel state `hasBadMacError` dan penguncian permanen pada `index.js`.
2. Mengubah endpoint `/status` agar hanya memeriksa keberadaan socket user aktif (`sock?.user ? 'connected' : 'disconnected'`).
3. Mengizinkan Baileys menangani perbaikan sesi enkripsi secara internal tanpa merusak pelaporan status koneksi global.

## Status
✅ Terselesaikan dan sudah di-*deploy*. Indikator web kini akurat menampilkan status **Terhubung ✅**.
